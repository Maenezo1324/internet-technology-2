# Задание 1. CJM и План отслеживания событий (Elfsight)

## 1. Customer Journey Map (CJM): Оформление первой подписки
Сценарий охватывает путь от первого визита до успешной оплаты первого тарифа.

| Этап | Действия пользователя | Точки контакта | Возможные барьеры |
|---|---|---|---|
| **1. Осведомленность** | Переход на сайт Elfsight, изучение каталога виджетов. | Лендинг, Каталог виджетов | Непонятна ценность продукта, нет нужного виджета. |
| **2. Регистрация** | Нажатие "Sign Up", ввод email/пароля или OAuth (Google). | Форма регистрации | Слишком много полей, отказ от авторизации. |
| **3. Создание виджета** | Выбор шаблона, настройка визуала и контента виджета. | Редактор виджета | Сложный интерфейс, виджет не подходит под дизайн сайта. |
| **4. Интеграция (Публикация)** | Нажатие "Add to website" / "Publish". | Модальное окно с кодом | Пользователь не знает, как вставить код на свой сайт. |
| **5. Пейвол (Paywall)** | Достижение лимита бесплатных просмотров (или желание убрать лого Elfsight). Переход на Pricing. | Страница Pricing | Цены кажутся высокими, непонятны отличия тарифов. |
| **6. Оплата (Checkout)** | Выбор тарифа (Basic/Pro), ввод данных карты, подтверждение. | Форма оплаты (Stripe/др.) | Ошибка транзакции, нет нужного метода оплаты. |

## 2. Event Tracking Plan (План отслеживания)
События спроектированы в формате `Object_Action` для удобства разработки и анализа в системах типа Amplitude/Mixpanel.

| Event Name | Event Properties | Описание |
|---|---|---|
| `page_view` | `page_url`, `page_category` | Просмотр любой страницы сайта. |
| `sign_up_start` | `source`, `method` (email, google) | Открытие формы регистрации. |
| `sign_up_complete` | `user_id`, `method` | Успешное создание аккаунта. |
| `widget_create_start`| `widget_type`, `template_name` | Клик по шаблону виджета для настройки. |
| `widget_publish` | `widget_id`, `widget_type` | Генерация кода виджета (нажатие Publish). |
| `pricing_page_view` | `source_trigger` (menu, limit_reached) | Просмотр страницы с тарифами. |
| `plan_select` | `plan_name`, `billing_cycle` (monthly, annual) | Клик по кнопке выбора конкретного тарифа. |
| `checkout_start` | `plan_name`, `price` | Переход на форму ввода данных карты. |
| `checkout_complete` | `plan_name`, `revenue`, `currency` | Успешное списание средств (успешная подписка). |

## 3. Приоритизация внедрения событий
Для быстрого запуска аналитики и поиска точек роста события разделены на 3 приоритета (от критических к поведенческим).

**Priority 0 (Критические - Внедрить немедленно):**
* `sign_up_complete`, `widget_publish`, `checkout_complete`.
* *Обоснование:* Это скелет базовой воронки "Регистрация -> Активация -> Деньги". Без этих событий мы не сможем посчитать базовую конверсию и выручку.

**Priority 1 (Важные для поиска отвалов):**
* `pricing_page_view`, `plan_select`, `checkout_start`.
* *Обоснование:* Эти события раскрывают "черный ящик" монетизации. Они покажут, где отваливаются люди, готовые платить: пугают ли их цены (`pricing_page_view` -> `plan_select`) или отпугивает форма оплаты (`checkout_start` -> `checkout_complete`).

**Priority 2 (Глубокий UX и микроконверсии):**
* `widget_create_start`, `sign_up_start`.
* *Обоснование:* Эти события нужны продакт-менеджерам для оптимизации самого редактора и UI, но они вторичны по отношению к бизнес-метрикам.
